How It Works
One command. Eight steps.

A single argus scan command runs the full pipeline — no configuration required for public repos. Typical scan time: 3–8 minutes depending on repo size.

01
Clone repository
Clones the target (public or private with token auth) and discovers all source files across 10+ languages.
02
Triage-select files
For large repos, an LLM reviewer selects the 60 most security-relevant files to keep scan time and cost predictable.
03
Parallel LLM analysis
Each selected file is analyzed in parallel by an LLM security reviewer trained to find injection, auth, and logic flaws.
04
Run 7 security scanners
gitleaks, semgrep, gosec, cppcheck, pip-audit, grype, and lizard run concurrently alongside the LLM analysis.
05
Synthesize findings
All findings from LLM and tool scanners are merged into a single deduplicated list with severity scoring.
06
Validate and score
A validator agent reviews each finding for false positives, assigns confidence scores, and flags borderline cases.
07
Prioritize remediations
Findings are ranked by severity × ease-of-fix and grouped into actionable remediation tasks with effort estimates.
08
Generate report
Produces a Markdown + HTML report with executive summary, risk table, detailed findings, and scan coverage checklist.

Infrastructure
Built on Armature

The entire Argus pipeline is declared in two Armature workflow specs (repo-scan.yaml and iso25010-scan.yaml) and executed as a directed acyclic graph of LLM agents, tool calls, and shell adapters. Both workflows score LOW risk under Armature's static governance system.

Learn about Armature →
▸ Fan-out / Fan-in — parallel per-file analysis scales to any repo size
▸ Model tier routing — small models for analysis, frontier for synthesis
▸ Cross-run memory — remembers false positive patterns across scans
▸ Checkpoint / resume — long scans recover gracefully from crashes
▸ Strict safety mode — fail-closed tool governance, explicit allow rules
▸ Self-improvement — auto-applies spec improvements when scan quality drops
